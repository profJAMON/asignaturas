Vuestra web ya está en Internet

He conectado el repositorio de cada pareja con Cloudflare, una empresa con miles de servidores repartidos por el mundo. A partir de hoy funciona así:

  1. Subís los archivos a GitHub, como cada semana.
  2. Cloudflare se da cuenta de que hay cambios y copia los archivos a sus servidores.
  3. En uno o dos minutos, la web publicada ya tiene los cambios.

No tenéis que hacer nada nuevo: subir a GitHub ya es publicar. Os daré la dirección de vuestra web, que acaba en .pages.dev. Apuntadla y guardadla en marcadores.

⚠️ Como subir es publicar, lo que subáis lo puede ver cualquiera. Antes de subir, revisad que no hay datos personales, fotos vuestras ni textos de los que os podáis arrepentir.
Esta web es para este curso. Al terminar, la retiraré de Cloudflare. El código seguirá en GitHub.

Cómo llega tu web a una pantalla

Cuando alguien escribe la dirección de vuestra web en su móvil, pasan muchas cosas en menos de un segundo. Esto está muy relacionado con lo que veis en Instalación y mantenimiento de redes:

Publicar pasa una vez por cambio; visitar pasa cada vez que alguien abre la web.

  1. Subís los archivos a GitHub.
  2. Cloudflare los copia a sus servidores. Un servidor es un ordenador encendido día y noche que entrega archivos a quien se los pide.
  3. El visitante escribe la dirección. Pero los ordenadores no se buscan por nombres, sino por direcciones IP (números como 104.21.35.12). Por eso el navegador pregunta a un servidor DNS: "¿qué IP tiene esta dirección?". El DNS es como la agenda de contactos de Internet.
  4. Con la IP, el navegador pide los archivos al servidor de Cloudflare.
  5. El servidor se los envía y el navegador lee el HTML, el CSS y el JavaScript y dibuja la página.

Pregúntale al DNS: nslookup

  1. En VS Code: menú Terminal → New Terminal (Nuevo terminal). Se abre abajo una ventana para escribir órdenes.
  2. Escribid nslookup, un espacio y la dirección de vuestra web sin https://. Pulsad Intro.
  3. Después, lo mismo con la web de clase: nslookup asignaturas.profesorjamon.workers.dev.

Os saldrá algo así. Los números de vuestra pantalla serán otros:

> nslookup pixel-kart.pages.dev
Servidor:  UnKnown
Address:  192.168.1.1
↑ A: a quién preguntas

Respuesta no autoritativa:
Nombre:  pixel-kart.pages.dev
Addresses:  2606:4700:3036::ac43:a0e
            172.66.44.10
↑ B: lo que te contesta
  • Lo de arriba (A) es a quién le has preguntado: el DNS del instituto. No es la dirección de vuestra web.
  • Lo de abajo (B) es la respuesta. Salen varias: unas con puntos y otras, más largas, con dos puntos. Es normal.
🤔 Antes de seguir: ¿de quién son las direcciones que os ha contestado?

De Cloudflare. Vuestra web no tiene una IP «suya»: está en los servidores de Cloudflare, que guardan y entregan miles de webs a la vez, también la web de clase. Por eso las direcciones de las dos se parecen.

Mira cómo llegan los archivos: F12 → Red

  1. Abrid vuestra web publicada en Chrome y pulsad F12.
  2. Pestaña Red (en inglés, Network).
  3. Pulsad Ctrl + F5 para recargar.

Vais a ver llegar, uno por uno, index.html, las imágenes y el resto de archivos. Es el paso 5 del dibujo: el servidor os los envía y el navegador dibuja la página con ellos.

💡 Si la terminal no se abre o nslookup no contesta, la red del instituto lo está bloqueando: os lo enseño yo en el proyector.

Antes de seguir

¿Qué tenéis que hacer para que un cambio salga en la web publicada?

Subir los archivos a GitHub y esperar uno o dos minutos. Cloudflare publica los cambios solo.

¿Para qué sirve el DNS?

Para traducir la dirección web (un nombre) a la dirección IP del servidor (un número), que es lo que necesita el navegador para pedir los archivos.

Si apagáis vuestro ordenador, ¿se sigue viendo la web publicada? ¿Por qué?

Sí, porque los archivos están copiados en los servidores de Cloudflare, que siempre están encendidos. Vuestro ordenador solo hace falta para hacer cambios.

3. Trabajar seguros con el ordenador

Pasáis muchas horas delante de la pantalla, igual que un programador. En Instalación y mantenimiento de redes visteis los riesgos de trabajar con pantallas: si no os acordáis, repasad la sesión de carga física y pantallas. En sobre.html, un apartado "Trabajar seguros" con frases con huecos y su «porque», como el de la sesión 6:

  • 2 riesgos: «Un riesgo de pasar muchas horas con el ordenador es ___. Se evita con ___ porque ___».
  • Quién hace qué: «A la empresa le toca ___ (sillas, luz, pausas…). A quien trabaja le toca ___ (postura, descansos…)».
  • El precio de una cosa que protege: «Un ___ cuesta ___ euros en ___ (tienda online)».
  • Una mejora para nuestra aula: «En nuestra aula pondríamos ___ porque ___».
Ideas para los huecos

Riesgos: dolor de espalda, de cuello, de muñeca, ojos cansados, dolor de cabeza. Cómo se evitan: silla regulable, pantalla a la altura de los ojos, pausas cada hora, mirar lejos de vez en cuando, reposamuñecas, buena luz sin reflejos.
