Para qué sirve un formulario

Un formulario es la parte de una web donde el visitante escribe o elige algo: buscar, apuntarse a un torneo, hacer un test, calcular un precio...

Hoy haremos solo la parte de HTML: las cajas, las opciones y el botón. Por ahora, al pulsar el botón no pasará nada. En la parte de JavaScript haremos que el formulario funcione de verdad.

Las piezas de un formulario

Así es el formulario de inscripción al torneo de Pixel Kart:

<form>
    <label for="alias">Tu alias:</label>
    <input type="text" id="alias" placeholder="Por ejemplo: RayoAzul">

    <label for="edad">Edad:</label>
    <input type="number" id="edad" min="12" max="99">

    <label for="piloto">Piloto favorito:</label>
    <select id="piloto">
        <option>Turbo Rex</option>
        <option>Nube Veloz</option>
        <option>Chispa</option>
    </select>

    <button type="button">Inscribirme</button>
</form>

EtiquetaPara qué sirve
<form>Agrupa todo el formulario.
<label>El texto que explica qué hay que poner en cada caja.
<input>Una caja para escribir. No se cierra.
<select> y <option>Un desplegable con opciones para elegir.
<button>Un botón.

Tipos de <input>

El atributo type cambia qué se puede escribir en la caja:

typeQué hace
textTexto normal.
numberSolo números. Con min y max pones límites.
emailUn correo electrónico.
dateUna fecha, con calendario.
checkboxUna casilla para marcar.

placeholder es el texto gris de ejemplo que se ve dentro de la caja vacía.

La pareja label + id

El for del <label> tiene que ser igual que el id de su caja. Así quedan unidos: si pulsas el texto, el cursor salta a la caja.

El id es un nombre único para un elemento: no puede haber dos iguales en la misma página. Además, será la forma de encontrar cada caja desde JavaScript, así que ponle nombres claros: id="alias" sí, id="caja1" no.

¿Por qué type="button"?

Un botón dentro de un <form>, si no le dices nada, envía el formulario y la página se recarga (se borra lo escrito). Como nosotros no enviaremos datos a ningún sitio, ponemos siempre type="button".

Privacidad en los formularios

⚠️ Vuestra web estará publicada. No pidáis datos personales: nada de nombre y apellidos, teléfono, dirección ni DNI. Pedid alias, opiniones, gustos, cantidades... Y recordad que el formulario no enviará nada a ningún sitio: lo que se escriba solo lo usará JavaScript en esa misma página.

Antes de seguir

Pulsas el texto de un label y el cursor no va a la caja. ¿Qué falla?

El for del <label> no coincide con el id del <input>.

Quieres que el visitante elija su nivel entre "Principiante", "Medio" y "Experto". ¿Qué usas?

Un <select> con tres <option>.

Pulsas el botón y todo lo que habías escrito se borra. ¿Por qué?

Al botón le falta type="button": está enviando el formulario y la página se recarga.

Reto de hoy

Pensad qué podría hacer vuestra web con un formulario (un test, una calculadora, una encuesta, elegir algo y ver una recomendación...) y cread la parte de HTML:

  • Un <form> en la página que tenga más sentido para vuestro tema.
  • Al menos 2 cajas <input> de tipos distintos y un <select> con 3 opciones o más.
  • Cada caja con su <label>, y pulsando el texto el cursor salta a la caja.
  • Todos los id distintos y con nombres que dicen qué son.
  • Un <button type="button">.
  • Ningún campo pide datos personales.
  • Un comentario HTML encima del formulario que explique qué queréis que haga cuando funcione. Por ejemplo: <!-- Cuando funcione: dirá qué piloto te va mejor -->
Pista: no se me ocurre para qué usar el formulario

Ideas según el tema. Música: elige tu estado de ánimo y te recomiendo una canción. Recetas: escribe cuántas personas sois y te calculo los ingredientes. Deporte: escribe los goles de cada equipo y te digo quién gana. Videojuegos: responde 3 preguntas y te digo qué personaje eres.
