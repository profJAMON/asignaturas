Cómo son las presentaciones

Hoy cada pareja presenta su web. El orden os lo dije en la sesión 19. Antes de empezar tendré todas las webs abiertas en el ordenador del proyector.

  1. Recorrido por la web (4 minutos entre los dos): enseñáis las páginas, lo que funciona con JavaScript y vuestra idea de empresa. Unos 2 minutos cada uno.
  2. Preguntas (5 minutos para cada uno): abrís VS Code y os hago 3 preguntas a cada uno por separado, distintas para cada uno: una de vuestro código, una de vuestra hoja de la ficha de empresa y una de "Cómo llega mi web a tu pantalla".

Cada pareja tarda unos 14 minutos en total. El alumno que trabaja solo, unos 9.

La nota de la presentación es individual. No cuenta si hablas bien en público o si estás nervioso: cuenta si entiendes el código de tu web y sabes explicar qué hace.

Qué tipo de preguntas os haré

TipoEjemplo
Vuestro código"¿Qué hace esta línea?", "¿Qué pasa si borro el Number()?", "¿Dónde cambiarías el color del menú?"
Vuestra empresa"¿Qué riesgo tiene vuestro departamento de…?", "¿Dónde pondrías a Cloudflare en el mapa?", "¿De qué tipo es vuestra empresa?"
Cómo llega"¿Qué hace el DNS?", "¿De quién es la dirección que te da nslookup?", "¿Qué empresa hace este paso?"

Si no sabes una respuesta, puedes buscarla en vuestro código o en vuestra página mientras piensas en voz alta. Eso también cuenta: demuestra que sabes dónde mirar. Si te bloqueas, te vuelvo a hacer la misma pregunta con la página delante.

Mientras presentan los demás

  • Escuchad y fijaos en qué han hecho distinto a vosotros.
  • Apuntad una cosa que os haya gustado de cada web.

Al acabar todas las presentaciones, presenta quien faltó o no pudo acabar.

Entrega final

La versión que está en GitHub al empezar la clase de hoy es la que evalúo como web final. Después de presentar no se pueden hacer más cambios.

  • Todo subido a GitHub antes de empezar la clase.
  • La web publicada se ve bien y sin errores en la consola.
  • Tenéis a mano la dirección de la web y la carpeta abierta en VS Code para enseñar el código.
