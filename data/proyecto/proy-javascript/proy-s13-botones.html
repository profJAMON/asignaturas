Hoy: haces que JavaScript cambie los textos de la página y que un botón haga algo al pulsarlo. Trabajas solo, en tu carpeta de ejercicios.

La receta de un botón

Casi todo lo que haremos con JavaScript sigue la misma receta de tres pasos:

  1. Buscar en la página los elementos que vas a usar.
  2. Esperar a que alguien pulse el botón.
  3. Hacer algo cuando lo pulse.

Hoy la aprendes por partes: primero buscar y cambiar un texto; después, esperar al clic.

Buscar un elemento: querySelector

Para que JavaScript encuentre un elemento, le pones un id en el HTML:

<p id="dato">Pixel Kart tiene 8 pilotos.</p>
let dato = document.querySelector("#dato");
  • document es la página.
  • querySelector busca en ella el elemento que le pides.
  • Entre comillas va un selector, igual que en CSS: "#dato" busca el elemento con id="dato".
  • Lo que encuentra se guarda en una variable, para usarlo después.
⚠️ En el HTML: id="dato", sin almohadilla. En JavaScript: "#dato", con almohadilla. Es el mismo lío que con el punto de las clases.

Cambiar un texto: textContent

textContent es el texto que hay dentro de un elemento. Si le das un valor con =, lo sustituye:

  • Cambia el texto nuevo por otro.
  • Borra la segunda línea: ¿qué texto se ve ahora?
  • Quita la # del querySelector. ¿Qué dice la consola?

En el HTML sigue poniendo "Pixel Kart tiene 8 pilotos.", pero en la página se ve el texto nuevo: JavaScript lo ha cambiado al cargar.

💡 Truco de VS Code: en el HTML, escribe p#dato y pulsa Tab. VS Code escribe <p id="dato"></p>. Funciona con cualquier etiqueta: button#boton-dato + Tab.

Esperar al clic: addEventListener

Ahora el cambio no se hace al cargar la página, sino al pulsar un botón. Esta es la receta completa:

  • Pulsa el botón del resultado.
  • Añade console.log("clic"); dentro de las llaves y pulsa varias veces.
  • Cambia el texto del dato por otro.
  • Borra el }); del final. ¿Qué dice la consola?
  • addEventListener significa "quédate escuchando". Le dices qué esperar ("click") y qué hacer.
  • Lo que va entre las llaves { } no se ejecuta al cargar la página: se ejecuta cada vez que se pulsa el botón.
  • Se cierra con });: la llave cierra la función, el paréntesis cierra addEventListener y el punto y coma acaba la orden.
💡 Copia esta estructura tal cual y cambia solo lo de dentro. Nadie la escribe de memoria las primeras veces.
🤔 Antes de seguir: pones un console.log dentro de las llaves del addEventListener. ¿Cuándo sale el mensaje en la consola?

Cada vez que se pulsa el botón. Al cargar la página no sale nada.

El error más común

Si en la consola sale esto:

Uncaught TypeError: Cannot read properties of null (reading 'addEventListener')

significa que querySelector no encontró nada (null quiere decir "nada"). Las causas:

  • El id del HTML y el del JavaScript no coinciden letra a letra.
  • Falta la # en el JavaScript.
  • El <script> no está al final del <body>.
  • El .js es de otra página, que no tiene ese elemento. Por eso cada página tiene su propio .js.

Aquí tienes uno roto. Pulsa el botón, lee la consola y arréglalo:

  • Compara letra a letra el id del HTML con el del JavaScript.
  • Cuando lo arregles, la consola queda vacía y el botón funciona.
🤔 Antes de seguir: ¿qué busca document.querySelector("#resultado")?

El elemento de la página que tiene id="resultado".

💡 Truco de VS Code: en el .js, escribe boton.addE. VS Code te sugiere addEventListener: pulsa Tab y lo escribe entero, sin faltas. Si la lista no sale, pulsa Ctrl + Espacio. Funciona igual con textContent y querySelector.
