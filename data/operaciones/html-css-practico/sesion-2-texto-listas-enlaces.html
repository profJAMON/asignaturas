Texto importante y texto enfatizado

<p>Esto es <strong>muy importante</strong> y esto está <em>enfatizado</em>.</p>

Esto es muy importante y esto está enfatizado.

  • <strong> → el texto es importante (normalmente en negrita).
  • <em> → énfasis (normalmente en cursiva).

Existen <b> y <i>, pero solo cambian el aspecto visual sin decir por qué ese texto es especial — importa, por ejemplo, para lectores de pantalla. Usamos <strong>/<em> como norma en esta asignatura.

⚠️ La etiqueta <font> está eliminada de HTML moderno. El aspecto del texto lo controlaremos con CSS, no con etiquetas HTML.

Comentarios

Un comentario es texto que escribes en el código para dejar notas para ti mismo o para quien lea el código después — el navegador lo ignora por completo, nunca aparece en la página.

Sirven para explicar por qué has hecho algo de una manera concreta, para dejar recordatorios ("falta añadir la imagen aquí"), o para desactivar temporalmente un trozo de código sin borrarlo mientras haces pruebas.

<!-- Esto es un comentario, no se muestra en el navegador -->
<p>Esto sí se ve.</p>
<!-- <p>Esto no se ve, está comentado</p> -->

Lo importante de un comentario es precisamente lo que no aparece en la página renderizada:

Esto sí se ve.

Ni el comentario ni el párrafo comentado dejan ningún rastro visible — solo existen en el código fuente (Ctrl+U en el navegador para verlo).

💡 En VS Code no hace falta escribir <!-- y --> a mano: selecciona una línea (o varias) y pulsa Ctrl+/ (en Mac, Cmd+/). Vuelve a pulsarlo para descomentar.

Listas

No ordenadas (con viñetas)

<ul>
    <li>Elemento 1</li>
    <li>Elemento 2</li>
</ul>

Así se ve:

  • Elemento 1
  • Elemento 2

El tipo de viñeta se controla con CSS (list-style-type), que veremos más adelante. Por ahora, así se ven las tres más comunes:

  • disco (por defecto)
  • círculo
  • cuadrado

Ordenadas (numeradas)

<ol>
    <li>Primer paso</li>
    <li>Segundo paso</li>
</ol>

Así se ve:

  1. Primer paso
  2. Segundo paso

Con el atributo type puedes cambiar la numeración:

  1. números (por defecto)
  1. letras minúsculas
  1. números romanos
<ol type="a">...</ol>

Listas anidadas

La lista anidada va dentro de la etiqueta <li>, no después. Compara estos dos ejemplos:

✅ Correcto

<ul>
    <li>Frontend
        <ul>
            <li>HTML</li>
            <li>CSS</li>
        </ul>
    </li>
    <li>Backend</li>
</ul>
  • Frontend
    • HTML
    • CSS
  • Backend

❌ Incorrecto — aquí la lista anidada está fuera del <li>, como si fuera un elemento independiente:

<ul>
    <li>Frontend</li>
    <ul>
        <li>HTML</li>
        <li>CSS</li>
    </ul>
    <li>Backend</li>
</ul>
Visualmente puede llegar a parecer casi igual, pero para el navegador (y para un lector de pantalla) "HTML" y "CSS" ya no son parte de "Frontend": están sueltos al mismo nivel. Es un error de significado, no solo de estética.

Ejercicio guiado 1 — Encuentra el fallo

Copia esto en tu prueba.html y ábrelo con Live Server:

<ul>
    <li>Asignaturas
    </li>
    <ol>
        <li>Ofimática</li>
        <li>Operaciones básicas</li>
    </ol>
    <li>Hobbies</li>
</ul>

Sin mirar el ejemplo de arriba: ¿dónde está el fallo? Corrígelo para que la lista <ol> quede correctamente anidada dentro de "Asignaturas".

Pista 1

El fallo está en dónde empieza la <ol>, no en cómo está escrita por dentro (sus dos <li> están bien). Fíjate en qué hay justo antes de que abra la <ol>.

Pista 2

El </li> de "Asignaturas" se cierra antes de que empiece la <ol>, así que la lista numerada queda fuera, al mismo nivel que los demás <li>, en vez de dentro de uno de ellos. Compara con el ejemplo de "Frontend" de arriba: ¿el cierre </li> de "Asignaturas" va antes o después de la <ol>?

Si lo has corregido bien: al ver la lista en Live Server, "Ofimática" y "Operaciones básicas" aparecerán sangrados por debajo de "Asignaturas", como una sublista suya — no como dos elementos sueltos al mismo nivel que "Hobbies".

Ejercicio guiado 2 — Copia lo que ves

Borra lo que tengas dentro del <body> de tu prueba.html. Escribe el código para que se vea como en la imagen.

  • ① Una lista con viñetas.
  • ② Una lista con números.
  • ③ Una lista con letras.
  • ④ Una lista con números romanos.
  • ⑤ Una lista con otra lista dentro de cada elemento.
Pista 1

Para cada número, pregúntate primero: ¿lleva viñetas (<ul>) o lleva números (<ol>)?

Pista 2

③ y ④ son <ol> con el atributo type: busca más arriba qué valor da letras y cuál da números romanos. En ⑤, la lista pequeña va dentro del <li>, como en el ejemplo de "Frontend".

Si lo has hecho bien: en ⑤, las viñetas de "Fútbol", "Baloncesto", "Rock" y "Rap" son círculos vacíos. No lo escribes tú: el navegador las cambia solo cuando una lista va dentro de otra.

Enlaces

<a href="https://www.google.com">Ir a Google</a>
Ir a Google

Para que el enlace se abra en una pestaña nueva, añade target="_blank".

Enlace local a otro archivo tuyo: <a href="sobre-mi.html">Sobre mí</a>

Ancla dentro de la misma página:

<h2 id="css">CSS</h2>
...
<a href="#css">Ir a la sección CSS</a>
🤔 Antes de seguir: ¿qué diferencia hay entre href="pagina.html", href="https://..." y href="#seccion"? ¿A dónde lleva cada uno?
Ver la respuesta

href="pagina.html" es una ruta relativa: lleva a otro archivo HTML dentro de tu propia carpeta de proyecto. href="https://..." es una URL completa: lleva a otra web, fuera de tu proyecto. href="#seccion" es una ancla: no cambia de página, salta dentro de la misma página hasta el elemento que tenga id="seccion".

Práctica

Ahora lo pones en tu index.html. En la imagen tienes la web de ejemplo de PixelRojo con todo lo que tienes que añadir. Cada número de la imagen es un punto de la lista de abajo.

  • ① Una lista <ul> con al menos 3 temas de la asignatura, y una <ol> dentro de uno de ellos.
  • ② Un párrafo con al menos una palabra en <strong> y otra en <em>.
  • ③ Un comentario explicando qué sección estás a punto de crear (usa Ctrl+/).
  • ④ Un enlace externo a alguna web relacionada con lo que estás estudiando.
  • ⑤ Un enlace ancla que salte a una sección de tu propia página.

No hace falta que quede igual que la imagen: el texto es el tuyo y el orden lo eliges tú. Lo que cuenta es que estén las cinco cosas.

Si lo has hecho bien: al hacer clic en tu enlace ancla, la página salta a esa sección sin abrir una pestaña nueva, y en la dirección se añade # y el nombre de la sección.

Retos

Los tres retos son obligatorios, en orden.

Reto 1 — Tus webs favoritas

En tu index.html, añade un apartado "Mis webs favoritas" con 3 webs que uses. Cada una lleva su enlace y, debajo, una frase que diga para qué la usas.

  • ① Una lista <ol> con 3 webs.
  • ② Cada web es un enlace que se abre en una pestaña nueva (target="_blank").
  • ③ Debajo de cada enlace, una lista <ul> con una frase: para qué usas esa web.
  • ④ En cada frase, una palabra en <em>.

Si lo has hecho bien: al hacer clic en cada enlace, la web se abre en una pestaña nueva y tu página sigue abierta en la otra.

Reto 2 — Un índice con anclas

Añade un índice al principio de tu index.html: una lista <ol> con un enlace ancla por cada <h2> que tengas.

  • ① Una lista <ol> de enlaces, justo debajo de tu <h1>.
  • ② Cada <h2> de tu página tiene su id y su enlace en el índice.

Si lo has hecho bien: al hacer clic en cada enlace del índice, la página salta a su apartado.

Reto 3 — Una receta completa

Crea un archivo nuevo, receta.html, en tu carpeta mi-web, al lado de index.html. Escribe su estructura mínima (la de la sesión 1) y haz que se vea como en la imagen.

  • ① Un párrafo con una palabra en <strong> y otra en <em>.
  • ② Un enlace ancla que salta al apartado "Pasos".
  • ③ Una lista <ul> con los ingredientes.
  • ④ Una lista <ul> dentro del último ingrediente.
  • ⑤ Una lista <ol> con los pasos.
  • ⑥ Una lista <ol> con letras.
  • ⑦ Un enlace externo.
  • ⑧ Un comentario encima de cada <h2>.

Si prefieres otra receta, puedes cambiarla: lo que cuenta es que tenga las ocho partes.

Si lo has hecho bien: la pestaña del navegador muestra el título de la receta, y al hacer clic en el enlace ② la página baja hasta "Pasos".

Guarda esta versión de tu página. En la próxima sesión llegan las imágenes y la estructura semántica (<header>, <main>...), así que tenla organizada por bloques claros.
