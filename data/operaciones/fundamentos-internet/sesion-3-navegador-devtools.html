El navegador, por dentro

Ya sabes que el navegador le pide páginas a un servidor y las recibe de vuelta (lo viste en la sesión 1). Pero el navegador hace mucho más que "mostrar" lo que llega: interpreta el HTML, aplica el CSS, ejecuta el código y decide, byte a byte, qué dibuja en tu pantalla. Todo ese trabajo normalmente es invisible — pero el propio navegador trae un conjunto de herramientas para verlo por dentro, en tiempo real: las DevTools ("herramientas de desarrollador").

Cómo abrir las DevTools

Las DevTools no son un programa aparte que haya que instalar: vienen ya dentro de cualquier navegador moderno (Chrome, Firefox, Edge...). Hay varias formas de abrirlas, todas llevan al mismo sitio:

Los nombres pueden variar un poco según el navegador (por ejemplo, Firefox llama "Inspector" a lo que Chrome llama "Elements"), pero las tres pestañas que vas a usar en esta sesión existen en todos con una función equivalente.

Los tres paneles que vas a usar

Las DevTools tienen muchas pestañas, pero para empezar solo necesitas conocer bien estas tres.

Elements — la estructura de la página

Muestra el HTML y el CSS tal y como los está usando el navegador en ese preciso momento. Al pasar el ratón por una línea de código, se resalta en la página qué trozo dibuja; y al revés, al hacer clic sobre algo de la página, el panel salta a la línea de código que lo genera.

Console — mensajes y errores

Es donde el navegador "habla": avisa cuando algo ha ido mal (un archivo que no encuentra, código que falla) y también sirve para escribir instrucciones sueltas y ver el resultado al momento. Por ahora la usarás solo para leer, no para escribir código.

Network — lo que se ha descargado

Lista, uno por uno, todos los archivos que el navegador ha pedido para construir la página: el propio HTML, el CSS, las imágenes... Para cada uno indica si ha llegado bien (código de estado 200) o si ha habido un problema (por ejemplo 404, "no encontrado").

Nombre Tipo Estado Tiempo
index.html documento 200 12 ms
estilos.css hoja de estilos 200 8 ms
foto-perfil.jpg imagen 404 3 ms
favicon.ico imagen 200 4 ms

Fíjate en la fila de foto-perfil.jpg: el navegador la ha pedido, pero no la ha encontrado con ese nombre exacto — por eso aparece en 404 en vez de 200.

Actividades en el ordenador

Estas actividades sí se hacen en el ordenador, no en el cuaderno: la idea es que "toques" las DevTools tú mismo. Usa tu propia web personal (la que has ido construyendo) como página de pruebas — no vas a romper nada: lo que cambies aquí solo lo ves tú, en tu navegador, y desaparece en cuanto recargas.

Actividad 1 — Abre las DevTools

  1. Abre tu web personal en el navegador.
  2. Haz clic derecho en cualquier parte de la página y elige "Inspeccionar" (en algunos navegadores, "Inspeccionar elemento"). También puedes pulsar F12, o Ctrl+Shift+I (Cmd+Option+I en Mac).

Comprobación observable: se abre un panel nuevo, normalmente a un lado o abajo, con varias pestañas arriba: Elements, Console, Network…

Actividad 2 — Localiza un elemento

  1. Dentro de las DevTools, busca el icono con forma de flecha y recuadro (arriba a la izquierda del panel) y haz clic en él.
  2. Ahora haz clic sobre el título principal de tu página (tu <h1>).

Comprobación observable: en el panel Elements se resalta automáticamente la línea de código que corresponde a ese <h1>.

🤔 Antes de seguir: ¿por qué crees que esto es útil si tu página tuviera mucho código y no supieras dónde está escrita una parte concreta?
Ver respuestaPorque en vez de leer todo el HTML de arriba a abajo buscando dónde está ese texto, haces clic directamente sobre lo que ves en pantalla y las DevTools te llevan exactamente a esa línea de código.

Actividad 3 — Cambia algo temporalmente

  1. En el panel Elements, haz doble clic sobre el texto de tu <h1> (dentro del código, no en la página) y escribe otra cosa.
  2. Mira la página: el título ha cambiado de verdad en pantalla.
  3. Recarga la página con F5.

Comprobación observable: al recargar, el título vuelve a ser el original — el cambio no se guardó en ningún archivo, solo lo viste tú, un instante, en tu navegador.

🤔 Antes de seguir: ¿qué tendrías que hacer para que ese cambio de título fuera permanente, y no solo algo que ves un momento en las DevTools?
Ver respuestaEditar el archivo .html real con tu editor de código (no con las DevTools) y guardar el archivo. Las DevTools solo cambian lo que ves en ese momento en tu navegador; nunca tocan el archivo original.

Actividad 4 — El panel Styles (dentro de Elements)

  1. Con un elemento seleccionado en Elements, busca un panel llamado "Styles" (suele aparecer al lado o debajo del árbol de etiquetas).
  2. Localiza alguna propiedad CSS (por ejemplo color o font-size) y haz clic sobre su valor para cambiarlo.

Comprobación observable: el cambio se ve al instante en la página, igual que con el texto.

¿Dónde miro esto? Si algún día un elemento de tu página no tiene el color o el tamaño que esperabas, este es el panel donde comprobar qué reglas CSS se le están aplicando de verdad (y cuáles se están ignorando — suelen aparecer tachadas).

Actividad 5 — La pestaña Console

  1. Haz clic en la pestaña Console.
  2. Recarga la página (F5) con la consola abierta.

Comprobación observable: si tu página tiene algún problema (por ejemplo, un archivo que no carga bien), aparece un mensaje destacado con el nombre del archivo y la línea donde ocurre. Si no ves ningún mensaje así, es buena señal.

Puedes provocar uno a propósito: escribe mal, a mano, el nombre de tu archivo CSS en el <link> de tu HTML, guarda, recarga y mira qué aparece en la consola. Después deshaz el cambio.

¿Dónde miro esto? Cuando algo "no funciona" y no sabes por qué, la Console suele ser el primer sitio donde mirar: casi siempre te dice qué archivo y qué línea están fallando.

Actividad 6 — La pestaña Network

  1. Haz clic en la pestaña Network.
  2. Con esa pestaña abierta, recarga la página (F5).

Comprobación observable: aparece una lista con todos los archivos que tu navegador ha pedido para construir la página, cada uno con su código de estado.

🤔 Antes de seguir: si subieras una imagen a tu web pero escribieras mal su nombre en el <img src="...">, ¿qué esperarías ver en la pestaña Network para esa imagen?
Ver respuestaAparecería en la lista con el estado 404, porque el navegador la ha pedido pero no la ha encontrado con ese nombre exacto.

Actividad 7 — ¿Dónde lo miro? (integradora)

Para cada situación, decide en qué pestaña de las DevTools mirarías primero. Anótalo en el cuaderno, junto a las preguntas de esta sesión.

  • Un texto de tu página no tiene el color que esperabas.
  • Una imagen no llega a aparecer en tu página.
  • Has escrito algo en tu código y "no funciona", sin más pistas.
  • Quieres ver exactamente cómo está anidada una etiqueta dentro de otra.
Ver respuesta1) Elements → panel Styles. 2) Network → busca su fila y mira el estado. 3) Console → suele señalar archivo y línea. 4) Elements → el árbol de etiquetas.

Preguntas

  1. (V/F) Las DevTools son un programa aparte que hay que instalar, distinto del navegador.
  2. Explica con tus palabras qué significa "inspeccionar" una página web.
  3. (ABC) La forma más rápida de abrir las DevTools sin usar el ratón es:
    • a) haciendo doble clic en la barra de direcciones
    • b) pulsando F12
    • c) cerrando y abriendo el navegador
  4. Busca qué combinación de teclas abre las DevTools en el navegador que tú usas normalmente (puede variar según el sistema operativo).

Panel Elements

  1. (V/F) Si cambias un texto en el panel Elements, ese cambio se guarda en el archivo .html real.
  2. ¿Para qué sirve el icono con forma de flecha y recuadro dentro de las DevTools?
  3. (ABC) El panel "Styles", dentro de Elements, muestra:
    • a) los errores de la página
    • b) las reglas CSS que se aplican al elemento seleccionado
    • c) los archivos que se han descargado
  4. Si en el panel Styles ves una propiedad CSS tachada (con una línea encima), ¿qué crees que significa?
  5. Cuenta una situación real de tu propia web en la que te habría venido bien usar el panel Elements para encontrar dónde estaba escrito algo.

Panel Console

  1. (V/F) Un mensaje destacado en la Console siempre significa que la página no se ve en absoluto.
  2. ¿Qué dos datos suele dar un mensaje de error en la Console, además del propio mensaje?
  3. (ABC) Si tu archivo CSS no se aplica y ves un error en la Console sobre ese archivo, lo primero que deberías revisar es:
    • a) el color de fondo de tu página
    • b) que la ruta del archivo en el <link> sea correcta
    • c) el tamaño de la fuente
  4. En la Actividad 5 provocaste (o imaginaste) un error a propósito. ¿Qué información te dio la Console para saber dónde estaba el fallo?

Panel Network

  1. (V/F) El código de estado 200 significa que el archivo no se ha encontrado.
  2. ¿Qué código de estado esperarías ver si escribes mal el nombre de una imagen en tu <img src="...">?
  3. (ABC) La pestaña Network muestra:
    • a) solo los errores de tu código CSS
    • b) todos los archivos que el navegador ha pedido para construir la página
    • c) el historial de páginas que has visitado antes
  4. Busca qué significa el código de estado 500 y en qué se diferencia de un 404.
  5. Abre la pestaña Network en una página con muchas imágenes (por ejemplo, una noticia) y anota cuántos archivos se han cargado en total.

Repaso general

  1. Completa: "un archivo con estado ___ significa que se ha encontrado y cargado sin problema, mientras que un estado ___ significa que el navegador lo ha pedido pero no lo ha encontrado."
  2. Tienes una página en la que un botón no cambia de color al pasar el ratón por encima, como debería. ¿En qué panel de las DevTools mirarías primero, y qué esperarías encontrar?
  3. (ABC) Si quieres ver el código HTML y CSS de una página sin arriesgarte a estropear nada, la forma más segura es:
    • a) editando directamente el archivo en el servidor
    • b) usando las DevTools para inspeccionar, sin guardar ningún archivo
    • c) descargando la página entera a tu ordenador
  4. Con lo que has aprendido en esta sesión, escribe tú mismo una pregunta de tipo "¿dónde lo miro?" sobre una situación que se te ocurra, y respóndela indicando el panel correcto.
