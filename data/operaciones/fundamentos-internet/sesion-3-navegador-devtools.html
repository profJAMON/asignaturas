El navegador, por dentro

Ya sabes que el navegador le pide páginas a un servidor y las recibe de vuelta (lo viste en la sesión 1). Pero el navegador hace mucho más que "mostrar" lo que llega: interpreta el HTML, aplica el CSS, ejecuta el código y decide, byte a byte, qué dibuja en tu pantalla. Todo ese trabajo normalmente es invisible — pero el propio navegador trae un conjunto de herramientas para verlo por dentro, en tiempo real: las DevTools ("herramientas de desarrollador").

HTML y CSS: las dos palabras que vas a ver hoy

Toda página web está escrita con dos tipos de código:

CódigoQué decideEjemplo
HTMLQué hay en la página: títulos, textos, imágenes, enlaces.<h1>Mi web</h1> → un título
CSSCómo se ve: colores, tamaños, posiciones.color: red; → texto en rojo

Juntos, así:

  • Cambia Mi web por tu nombre: eso es el HTML (qué hay).
  • Cambia red por blue o green: eso es el CSS (cómo se ve).
📌 Todavía no tienes que saber escribir HTML ni CSS: lo aprenderás al final del curso, cuando crees tu propia web. Hoy solo vas a mirarlos por dentro de una página que ya existe.

Cómo abrir las DevTools

Las DevTools no son un programa aparte que haya que instalar: vienen ya dentro de cualquier navegador moderno (Chrome, Firefox, Edge...). Hay varias formas de abrirlas, todas llevan al mismo sitio:

1. Haz clic derecho sobre la página y elige Inspeccionar. Más rápido: pulsa F12.

2. Se abre un panel a un lado o abajo, con pestañas arriba. Si tu Chrome está en castellano: Elementos, Consola, Red…

👀 El Chrome del aula puede salir en castellano o en inglés. Las pestañas son las mismas con otro nombre:
En inglésEn castellanoPara qué sirve
ElementsElementosVer el HTML y el CSS de la página
StylesEstilosVer y cambiar el CSS de lo que has seleccionado (dentro de Elementos)
ConsoleConsolaLeer avisos y errores
NetworkRedVer los archivos que se han descargado

En esta sesión los verás escritos de las dos formas: «Elements (Elementos)».

Los tres paneles que vas a usar

Las DevTools tienen muchas pestañas, pero para empezar solo necesitas conocer bien estas tres.

Elements (Elementos) — la estructura de la página

Muestra el HTML y el CSS tal y como los está usando el navegador en ese preciso momento. Al pasar el ratón por una línea de código, se resalta en la página qué trozo dibuja; y al revés, al hacer clic sobre algo de la página, el panel salta a la línea de código que lo genera.

1. En el panel, arriba a la izquierda, pulsa el icono de la flecha dentro de un recuadro.

2. Ahora haz clic sobre algo de la página, por ejemplo el título grande.

3. En Elementos se resalta la línea de código que dibuja eso. El título empieza por <h1. Código y página están conectados.

Console (Consola) — mensajes y errores

Es donde el navegador "habla": avisa cuando algo ha ido mal (un archivo que no encuentra, código que falla) y también sirve para escribir instrucciones sueltas y ver el resultado al momento. Por ahora la usarás solo para leer, no para escribir código.

Network (Red) — lo que se ha descargado

Lista, uno por uno, todos los archivos que el navegador ha pedido para construir la página: el propio HTML, el CSS, las imágenes... Para cada uno indica si ha llegado bien (código de estado 200) o si ha habido un problema (por ejemplo 404, "no encontrado").

Nombre Tipo Estado Tiempo
index.html documento 200 12 ms
estilos.css hoja de estilos 200 8 ms
foto-perfil.jpg imagen 404 3 ms
favicon.ico imagen 200 4 ms

Fíjate en la fila de foto-perfil.jpg: el navegador la ha pedido, pero no la ha encontrado con ese nombre exacto — por eso aparece en 404 en vez de 200.

Actividades en el ordenador

Estas actividades sí se hacen en el ordenador, no en el cuaderno: la idea es que "toques" las DevTools tú mismo. Usa como página de pruebas esta misma página de mi web de materiales — no vas a romper nada: lo que cambies aquí solo lo ves tú, en tu navegador, y desaparece en cuanto recargas.

Actividad 1 — Abre las DevTools

  1. Abre esta misma página en Chrome (si ya la estás viendo, no hace falta hacer nada).
  2. Haz clic derecho en cualquier parte de la página y elige "Inspeccionar" (en algunos navegadores, "Inspeccionar elemento"). También puedes pulsar F12, o Ctrl+Shift+I (Cmd+Option+I en Mac).

Comprobación observable: se abre un panel nuevo, normalmente a un lado o abajo, con varias pestañas arriba: Elements, Console, Network… (o Elementos, Consola, Red).

Actividad 2 — Localiza un elemento

  1. Dentro de las DevTools, busca el icono con forma de flecha y recuadro (arriba a la izquierda del panel) y haz clic en él.
  2. Ahora haz clic sobre el título grande de esta sesión, el de arriba del todo.

Comprobación observable: en el panel Elements se resalta automáticamente la línea de código de ese título. Empieza por <h1: es la etiqueta HTML de los títulos principales. Lo que has hecho en las actividades 1 y 2 es la pregunta 4.

🤔 Antes de seguir: ¿por qué crees que esto es útil si una página tiene mucho código y no supieras dónde está escrita una parte concreta?
Ver respuestaPorque en vez de leer todo el código de arriba a abajo buscando dónde está ese texto, haces clic directamente sobre lo que ves en pantalla y las DevTools te llevan exactamente a esa línea de código.

Actividad 3 — Cambia algo temporalmente

  1. En el panel Elements, haz doble clic sobre el texto del título (dentro del código, no en la página) y escribe otra cosa.
  2. Mira la página: el título ha cambiado de verdad en pantalla.
  3. Recarga la página con F5.

Comprobación observable: al recargar, el título vuelve a ser el original: el cambio no se guardó en ningún archivo, solo lo viste tú, un instante, en tu navegador (pregunta 6).

🤔 Antes de seguir: ¿qué tendrías que hacer para que ese cambio de título fuera permanente, y no solo algo que ves un momento en las DevTools?
Ver respuestaCambiar el archivo .html real, el que está guardado en el servidor, y guardarlo. Eso solo lo puede hacer quien ha creado la web (en esta, yo). Las DevTools solo cambian lo que ves en ese momento en tu navegador; nunca tocan el archivo original.

Actividad 4 — El panel Styles (Estilos), dentro de Elements

  1. Con un elemento seleccionado en Elements, busca un panel llamado "Styles" o "Estilos" (suele aparecer al lado o debajo del árbol de etiquetas).
  2. Localiza alguna propiedad CSS (por ejemplo color, el color del texto, o font-size, el tamaño de letra) y haz clic sobre su valor para cambiarlo. Por ejemplo, cambia el color por red.

Comprobación observable: el cambio se ve al instante en la página, igual que con el texto. Apunta qué propiedad cambiaste y qué valor pusiste (pregunta 8).

¿Dónde miro esto? Si algún día un elemento de una página no tiene el color o el tamaño que esperabas, este es el panel donde comprobar qué reglas CSS se le están aplicando de verdad (y cuáles se están ignorando — suelen aparecer tachadas).

Actividad 5 — La pestaña Console

  1. Haz clic en la pestaña Console (Consola).
  2. Recarga la página (F5) con la consola abierta.

Comprobación observable: si la página tiene algún problema (por ejemplo, un archivo que no carga bien), aparece un mensaje destacado en rojo, con el nombre del archivo y la línea donde ocurre. Si no ves ningún mensaje rojo, es buena señal.

  1. Ahora abre otra web que uses a menudo (un periódico, una tienda…), abre su Console y recarga.

Comprobación observable: en las webs grandes es muy normal ver algún aviso (amarillo) o error (rojo). Anota en el cuaderno qué web has mirado y cuántos mensajes rojos has visto (pregunta 10).

¿Dónde miro esto? Cuando algo "no funciona" y no sabes por qué, la Console suele ser el primer sitio donde mirar: casi siempre te dice qué archivo y qué línea están fallando.

Actividad 6 — La pestaña Network

  1. Haz clic en la pestaña Network (Red).
  2. Con esa pestaña abierta, recarga la página (F5).

Comprobación observable: aparece una lista con todos los archivos que tu navegador ha pedido para construir la página, cada uno con su código de estado.

🤔 Antes de seguir: si quien ha hecho una web escribe mal el nombre de una imagen en el código, el navegador la pedirá con un nombre que no existe. ¿Qué esperarías ver en la pestaña Network para esa imagen?
Ver respuestaAparecería en la lista con el estado 404, porque el navegador la ha pedido pero no la ha encontrado con ese nombre exacto.

Actividad 7 — ¿Dónde lo miro? (integradora)

Para cada situación, decide en qué pestaña de las DevTools mirarías primero. Es la pregunta 15: anótalo en el cuaderno.

  • Un texto de una página no tiene el color que esperabas.
  • Una imagen no llega a aparecer en una página.
  • Algo de una página "no funciona", sin más pistas.
  • Quieres ver exactamente cómo está anidada una etiqueta dentro de otra.
Ver respuesta1) Elements → panel Styles. 2) Network → busca su fila y mira el estado. 3) Console → suele señalar archivo y línea. 4) Elements → el árbol de etiquetas.
