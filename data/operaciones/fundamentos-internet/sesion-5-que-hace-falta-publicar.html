Qué hace falta para publicar una página

Hasta ahora has visto cómo un navegador encuentra y pide una página que ya existe en algún sitio de internet. Pero, ¿qué hace falta para que una página tuya llegue a existir ahí, visible para cualquiera? No es solo "tener el código terminado": hacen falta tres ingredientes más, y esta sesión es el puente hacia el bloque donde aprenderás a publicar de verdad.

Un dominio

Ya lo conoces de la sesión 1: el nombre que el DNS traduce a una IP (iesramonllull.net). Sin un dominio, la gente tendría que escribir tu dirección IP a pelo para visitarte — funciona, pero nadie se acuerda de un número.

Un hosting

Un dominio es solo un nombre: necesita apuntar a algún ordenador real que tenga tu página guardada y responda cuando alguien la pida. Ese ordenador se llama servidor, y contratar uno para que guarde y sirva tu web se llama hosting ("alojamiento").

Un mismo servidor de hosting suele guardar muchas webs a la vez, de clientes distintos, como un edificio con muchos pisos. Cada dominio apunta a su piso.

🤔 Antes de seguir: ¿por qué crees que no bastaría con dejar tu propio ordenador de casa encendido y conectado para "publicar" tu web ahí?
Ver respuestaPorque tendría que estar encendido y conectado permanentemente (si lo apagas o se corta la conexión, la web deja de responder), y además la mayoría de conexiones domésticas no están pensadas para eso: no tienen una dirección fija y estable pensada para recibir muchas visitas. El hosting resuelve justo eso: es un servidor profesional, siempre encendido, preparado para responder peticiones constantemente.

Un certificado HTTPS

En la sesión 4 viste que https:// significa que la conexión viaja cifrada. Ese cifrado no aparece solo: hace falta un certificado, un documento digital que confirma que el servidor es quien dice ser, emitido por una entidad de confianza. Sin él, el navegador avisa a todo el que visite tu web.

Los certificados caducan, como el DNI: duran unos meses y hay que renovarlos. Si nadie lo renueva, el navegador muestra una pantalla de aviso («La conexión no es privada») antes de dejarte entrar.

🤔 Antes de seguir: si entras en una web y el navegador avisa de que "no es segura", pero decides continuar igualmente, ¿qué es exactamente lo que esa web no te está garantizando?
Ver respuestaNo te garantiza que la información que viaja entre tu navegador y ese servidor esté cifrada: alguien que intercepte la conexión por el camino (por ejemplo, en una red wifi pública) podría llegar a leerla.

Los tres ingredientes juntos

Piensa en una tienda. El local es el hosting: sin él no tienes dónde poner nada. El rótulo de la puerta es el dominio: sin él, nadie sabe cómo encontrarte. Y lo que hay en las estanterías son tus páginas, el contenido. El HTTPS sería la cerradura de la puerta.

  • Dominio — el nombre por el que te van a encontrar.
  • Hosting — el servidor que guarda tu web y responde siempre, esté quien esté conectado y a la hora que sea.
  • HTTPS — el certificado que cifra la conexión entre el visitante y tu servidor.

Con el contenido terminado (las páginas de la web) más estos tres ingredientes, una web está lista para publicarse de verdad. El último paso —subir los archivos al servidor— lo harás tú mismo al final del curso, cuando hayas creado tu propia web.

De la URL a la pantalla: el viaje completo

Ahora que conoces todas las sesiones de esta unidad, puedes unir todas las piezas en un único recorrido.

1. Escribes la URL o pulsas un enlace (sesión 4). El navegador es el cliente (sesión 1).

2. El navegador pregunta al DNS qué IP tiene ese dominio (sesión 1). Es lo que ves con nslookup (sesión 2).

3. Con la IP, se conecta con el servidor del hosting. Si hay certificado, la conexión va cifrada con HTTPS: el candado.

4. Le manda la petición: el método GET y la ruta que quiere (sesión 4).

5. El servidor manda la respuesta: el código de estado (200) y el contenido. El navegador dibuja la página. Lo puedes ver en la pestaña Network o Red (sesión 3).
